# 天の声 Bot (Tennokoe Bot) - Go版

Discord通話間で音声を転送するためのボットシステムです。一つの通話（通話A）の音声を別の通話（通話B）にリアルタイムで転送し、様々な音声エフェクトを適用できます。

## 機能

### 基本機能
- **リスニングBot**: 指定したボイスチャンネルで音声をリッスン
- **スピーキングBot**: 指定したボイスチャンネルで音声を再生
- **リアルタイム音声転送**: 受信した音声を即座に別のチャンネルに転送
- **別々のチャンネル接続**: リスニングとスピーキングを異なるチャンネルに接続可能

### 音声エフェクト機能
- **通常**: エフェクトなしの音声
- **ビットクラッシュ**: レトロゲーム風の音質
- **ローパスフィルター**: 高音域をカットしたこもった音質
- **エコー**: 山びこ効果
- **ヘリウム声**: 高音化エフェクト

### コマンド
- `t!listen` - リスニングBot単体でのチャンネル選択接続
- `t!speak` - スピーキングBot単体でのエフェクト選択＋チャンネル接続
- `t!connect` - 両ボット同時接続（3ステップフロー）
- `t!disconnect` - 両ボットの切断

## 必要条件

- Go 1.16以上
- 2つのDiscord Botアカウント（トークン）
- CGO対応（Opus音声コーデック用）

## インストール方法

1. リポジトリをクローンまたはダウンロードします
```bash
git clone https://github.com/yourusername/tennokoe-bot.git
cd tennokoe-bot
```

2. 依存関係をインストールします
```bash
go mod download
```

3. `.env`ファイルを設定します
```env
# リスニング用ボットのトークン
LISTENING_BOT_TOKEN=あなたのリスニングボットトークンをここに入力

# スピーキング用ボットのトークン
SPEAKING_BOT_TOKEN=あなたのスピーキングボットトークンをここに入力
```

## ビルド方法

### Windows
```bash
go build -o tennokoe-bot.exe ./cmd/bot
```

### Linux/macOS
```bash
go build -o tennokoe-bot ./cmd/bot
```

## 使い方

### 1. プログラムの起動
```bash
./tennokoe-bot
```
Windowsの場合:
```bash
tennokoe-bot.exe
```

### 2. コマンドの使用

#### `t!connect` - 両ボット同時接続（推奨）
3ステップで両ボットを設定します：

1. **ステップ 1/3**: リスニングボット用チャンネル選択
   - 音声を受信するチャンネルを選択

2. **ステップ 2/3**: エフェクト選択
   - 通常、ビットクラッシュ、ローパスフィルター、エコー、ヘリウム声から選択

3. **ステップ 3/3**: スピーキングボット用チャンネル選択
   - 音声を再生するチャンネルを選択

#### `t!listen` - リスニングBot単体接続
- リスニングボットのみをチャンネルに接続
- チャンネル選択メニューが表示されます

#### `t!speak` - スピーキングBot単体接続
- エフェクト選択後、スピーキングボットをチャンネルに接続
- 2ステップ（エフェクト選択→チャンネル選択）で設定

#### `t!disconnect` - 切断
- 両方のボットを同時に切断

### 3. 使用例

**シナリオ**: チャンネルAの音声をチャンネルBにエコーエフェクト付きで転送

1. テキストチャンネルで `t!connect` を実行
2. リスニングチャンネルとして「チャンネルA」を選択
3. エフェクトとして「エコー」を選択
4. スピーキングチャンネルとして「チャンネルB」を選択
5. 完了！チャンネルAの音声がエコー付きでチャンネルBに転送されます

## 技術仕様

### 音声処理
- **コーデック**: Opus（Discord標準）
- **サンプリングレート**: 48kHz
- **チャンネル数**: 2（ステレオ）
- **フレームサイズ**: 960サンプル
- **ビットレート**: 64kbps

### アーキテクチャ
- **リスニングBot**: 音声受信 → PCMデコード → ミキサーに送信
- **AudioMixer**: PCMミキシング → エフェクト適用 → Opusエンコード
- **SpeakingBot**: Opusデータ受信 → 音声再生

### エフェクト処理
- **ビットクラッシュ**: ビット深度削減による音質劣化
- **ローパスフィルター**: 高周波成分の除去
- **エコー**: 遅延音の重ね合わせ
- **ヘリウム声**: 周波数シフトによる高音化

## Discord Botの作成方法

1. [Discord Developer Portal](https://discord.com/developers/applications)にアクセス
2. 「New Application」をクリックして2つのアプリケーションを作成
3. 各アプリケーションの「Bot」タブでボットを有効化
4. 「Reset Token」をクリックしてトークンを取得し、`.env`ファイルに設定
5. 「Privileged Gateway Intents」で以下を有効化:
   - SERVER MEMBERS INTENT
   - MESSAGE CONTENT INTENT
6. 「OAuth2」→「URL Generator」で権限を選択:
   - スコープ: `bot`
   - 権限: `Send Messages`, `Use Slash Commands`, `Connect`, `Speak`, `Use Voice Activity`

## ログ機能

- **自動ログ出力**: `logs/` ディレクトリに日時付きログファイルを生成
- **ログローテーション**: 7日以上古いログファイルを自動削除
- **詳細ログ**: 音声処理、接続状態、エラー情報を記録

## トラブルシューティング

### よくある問題

**ボットが接続できない**
- `.env`ファイルのトークンが正しいか確認
- ボットがサーバーに招待されているか確認
- ボットに必要な権限があるか確認

**音声が聞こえない**
- 両方のボットが正しいチャンネルに接続されているか確認
- スピーキングボットがミュート状態でないか確認
- リスニングチャンネルに音声入力があるか確認

**エフェクトが適用されない**
- エフェクト選択が正常に完了しているか確認
- ログでエフェクト適用メッセージを確認

**コマンドが反応しない**
- ボットがオンラインか確認
- コマンドの先頭が `t!` になっているか確認
- MESSAGE CONTENT INTENTが有効になっているか確認

### デバッグ方法

1. **ログファイルの確認**
   ```bash
   tail -f logs/tennokoe-bot-YYYY-MM-DD_HH-MM-SS.log
   ```

2. **音声処理の確認**
   - ログで `[AudioMixer]` メッセージを確認
   - `Processing audio data from X active sources` が表示されるか確認

3. **接続状態の確認**
   - ログで `Successfully connected` メッセージを確認
   - Discordでボットのオンライン状態を確認

## パフォーマンス

### 推奨環境
- **CPU**: 2コア以上
- **メモリ**: 512MB以上
- **ネットワーク**: 安定したインターネット接続

### 制限事項
- **同時接続**: 1サーバーあたり1組のボット接続
- **音声遅延**: 約50-100ms（ネットワーク環境による）
- **同時発話**: 複数ユーザーの音声は自動ミキシング
